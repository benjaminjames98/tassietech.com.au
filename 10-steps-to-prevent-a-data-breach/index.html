Data breach prevention is a set of practical habits: know where data lives, limit access, require MFA, patch systems, secure sharing, and test recovery.

Cybersecurity 15 Mar 2025 4 min read

Data breaches are rarely caused by one dramatic failure. More often, they come from ordinary gaps that line up badly: an old account that was never removed, a reused password, a public file link, an unpatched plugin, a remote access tool with weak MFA, or a backup that nobody checked. Prevention is not one control. It is a set of small controls that reduce the chance of those gaps lining up.

A useful way to frame the work is the NIST Cybersecurity Framework, which organises security around identifying, protecting, detecting, responding, and recovering. For a small business, that becomes a practical checklist: know what you have, protect the important parts, watch for problems, respond quickly, and recover cleanly.

1. Know where sensitive data lives

Start with the obvious locations: Microsoft 365 mailboxes, SharePoint sites, OneDrive folders, Dropbox workspaces, accounting systems, CRM tools, WordPress forms, website hosting, Synology NAS shares, laptops, and mobile devices. Then look for the less obvious locations: exported reports, old spreadsheets, email attachments, downloads folders, archived USB drives, and vendor portals.

You cannot apply sensible controls until you know where the data is. The inventory does not need to be perfect, but it should identify the information that would cause harm if it were exposed.

2. Reduce access to match the role

Permissions should reflect current work, not old convenience. Review SharePoint libraries, Dropbox folders, WordPress administrators, Microsoft 365 admin roles, remote support tools, NAS shares, and hosting panels. Remove old users and reduce admin rights wherever possible.

This is one of the least glamorous and most effective breach-prevention habits. If an account is compromised, the damage is limited by what that account can reach.

3. Require MFA on important accounts

MFA should be standard for email, Microsoft 365, password managers, banking, remote access, website administration, cloud storage, and network administration. NIST's guidance on multi-factor authentication is clear about the value of requiring more than a password for access.

4. Use a password manager

1Password or another reputable password manager helps staff stop reusing passwords and gives the business a safer way to manage shared admin credentials. It also makes offboarding cleaner because shared vault access can be reviewed and removed centrally.

5. Patch systems on a schedule

Unpatched software remains one of the simplest entry points. Patch operating systems, browsers, Microsoft 365 apps, WordPress core and plugins, remote access tools, NAS firmware, UniFi network equipment, and server software. For hosted services such as Synergy Web Servers, make sure there is a clear maintenance owner for the website and hosting environment.

6. Secure file sharing

Public links, broad external sharing, and old guest accounts can expose information long after a project ends. Review sharing settings in SharePoint, OneDrive, and Dropbox. Use named access where possible and expiry dates for temporary collaboration.

7. Protect endpoints and remote access

Laptops and remote tools are common breach pathways. Endpoint protection, encryption, screen locks, remote wipe, and named remote support access all matter. Splashtop can be a good support tool when MFA, user roles, and device lists are reviewed rather than left open-ended.

8. Segment the network

Guest Wi-Fi, IoT devices, staff devices, servers, and backups should not all sit in the same trust zone. UniFi networking can make this kind of segmentation practical for small offices. Even simple separation can reduce the impact of a compromised device.

9. Back up and test recovery

Backups are a breach-control measure because they reduce pressure during ransomware, deletion, or account compromise. The ACSC small business guide includes backups as a core practice for this reason. Test restoration, not just backup completion.

10. Make reporting easy

Staff should know how to report a suspicious email, lost device, accidental share, or strange login alert without embarrassment. Early reporting often prevents a small mistake from becoming a full breach. The best breach-prevention culture is calm, specific, and fast.
